# WG Bridge

[English](README.md) | **فارسی**

انتقال خروجی انتخاب‌شدهٔ پنل ایران به اینترنت سرور خارج، با WireGuard کرنل لینوکس. کاربران، پورت اینباندها و محاسبه مصرف در پنل خودتان باقی می‌مانند. مسیر پیش‌فرض اینترنت سرورها تغییر نمی‌کند؛ SSH و سرویس‌های دیگر مسیر عادی خود را حفظ می‌کنند.

اسکریپت ارتباط، مسیریابی اختصاصی، NAT خارج و جلوگیری از خروج مستقیم هنگام قطع تونل را تنظیم می‌کند. خروجی پنل را دستی به IP مبدأ **10.204.0.2** و رابط **wgb-exit** متصل می‌کنید. SOCKS یا پنل نصب نمی‌شود. چندین اینباند با پورت‌های متفاوت می‌توانند از همین خروجی استفاده کنند.

پورت پیش‌فرض ارتباط WireGuard در هر دو سرور **9999/UDP** است و موقع نصب قابل تغییر است. این پورت مستقل از پورت‌های اینباند پنل است.

## پیش‌نیازها

Ubuntu 22.04/24.04/26.04 LTS شامل 26.04.1 یا Debian 12/13، دسترسی root، systemd، کرنل دارای WireGuard و IPv4 عمومی روی هر دو سرور. پورت UDP انتخاب‌شده را در فایروال ارائه‌دهنده هر دو سرور باز کنید. پورت اینباندهای پنل نیز روی ایران باید مجاز باشد. سایر وابستگی‌ها خودکار نصب می‌شوند.

```bash
apt-get update && apt-get install -y curl ca-certificates
```

## اتصال دو سرور

1. ابتدا روی **خارج** گزینه **2 — Client** را انتخاب کنید. IP عمومی خارج و پورت WireGuard آن را تأیید کنید. سپس **IP عمومی ایران** و پورت WireGuard موردنظر برای ایران را وارد کنید. Enter مقدار پیش‌فرض رنگی را می‌پذیرد.
2. کد **WGB3** را کامل، همراه با ابتدای `WGB3.` کپی کنید. این کد کلید خصوصی دارد؛ در ویدیو مخفی نگه دارید و فقط روی یک سرور ایران استفاده کنید.
3. همان نصب‌کننده را روی **ایران** اجرا و گزینه **1 — Server** را انتخاب کنید. کد را پیست کنید؛ متن هنگام ورود دیده می‌شود. IP و پورت ایران باید با مقادیر ثبت‌شده روی خارج یکسان باشند.
4. روی ایران `wg-bridge doctor` را اجرا کنید. علاوه بر handshake، مسیر خروج، HTTPS از طریق خارج و DNS با UDP از داخل تونل بررسی می‌شود.
5. خروجی، Routing و DNS پنل را طبق راهنمای زیر دستی تنظیم کنید. اسکریپت دیتابیس، حساب کاربران یا تنظیمات پنل را تغییر نمی‌دهد.

هر دو سمت endpoint مشخص و keepalive برابر ۲۵ ثانیه دارند. هر نصب یک جفت سرور را مدیریت می‌کند. انتخاب پورت به‌تنهایی عبور از محدودیت شبکه را تضمین نمی‌کند؛ مسیر UDP بین دو سرور باید قابل استفاده باشد.

## تنظیم پنل

برای **ثنایی و سایر پنل‌های Xray**:

- Protocol: `freedom`
- Tag: `wg-out`
- Send Through: `10.204.0.2`
- Sockopts / Interface: `wgb-exit`
- راهبرد تبدیل دامنه به IPv4: `ForceIPv4`
- Redirect و Dialer Proxy خالی؛ Mark برابر `0`

در Routing، تگ اینباندهای کاربران را به `wg-out` هدایت کنید. قوانین داخلی API و مسدودسازی پنل را حفظ کنید. DNS پنل هم باید از همین خروجی عبور کند. ذخیره Outbound به‌تنهایی کاربران یا DNS را به آن متصل نمی‌کند.

**[راهنمای کامل پنل، DNS و نمونه JSON](docs/panels.fa.md)** · [English guide](docs/panels.md)

**پاسارگارد:** [راهنمای تنظیمات به فارسی](docs/pasarguard.fa.md) · [English setup guide](docs/pasarguard.md)

پنل‌های دیگر نیز اگر موتورشان انتخاب IP مبدأ یا رابط خروجی را پشتیبانی کند، می‌توانند از تونل استفاده کنند. نام فیلدهای sing-box در راهنما آمده؛ امکانات رابط کاربری هر پنل متفاوت است. پنل مستقیم روی میزبان یا Docker با شبکه host می‌تواند رابط را ببیند. Docker با شبکه bridge به تنظیم جداگانه نیاز دارد و در نصب خودکار پوشش داده نمی‌شود.

خروجی این نسخه **IPv4** است. مقصد IPv6 از تونل عبور نمی‌کند؛ ترافیک IPv6 متصل به رابط تونل مسدود می‌شود. IPv6 خود سرور برای سرویس‌های دیگر باقی می‌ماند. خروجی درست متصل‌شده به تونل هنگام قطع آن به اینترنت مستقیم برنمی‌گردد؛ قوانینی که در پنل عمداً خروجی دیگری را انتخاب کنند، مستقل هستند.

## مدیریت

```bash
wg-bridge
wg-bridge status
wg-bridge doctor
wg-bridge panel
```

دستور `wg-bridge` از هر مسیر منو را باز می‌کند. منو شامل وضعیت، عیب‌یابی، راه‌اندازی مجدد، توقف و شروع، کد اتصال، تنظیمات پنل و حذف است. سرویس‌ها بعد از روشن‌شدن سرور شروع می‌شوند. با توقف تونل، قواعد جلوگیری از خروج مستقیم باقی می‌مانند.

برای اصلاح endpoint ایران، روی **خارج** اجرا کنید:

```bash
wg-bridge peer IRAN_PUBLIC_IPV4 IRAN_WIREGUARD_UDP_PORT
```

جای دو عبارت، IP و پورت واقعی ایران را بنویسید. کلیدها و پورت خارج حفظ می‌شوند؛ کد اتصال به‌روز و تونل فعال مجدداً راه‌اندازی می‌شود. پورت گوش‌دادن ایران از راه دور عوض نمی‌شود.

## ارتقا و تبدیل نسخه 0.3

ابتدا روی **خارج** و سپس روی **ایران**:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/itsalirezaw/wg-bridge/main/install.sh) --upgrade
wg-bridge routing
```

ارتقا فقط مدیر را عوض می‌کند. `wg-bridge routing` حالت فوروارد پورت عمومی را به خروجی پنل تبدیل می‌کند و پس از پشتیبان‌گیری در `/etc/wg-bridge/before-panel-*` تونل را مجدداً راه‌اندازی می‌کند. کلیدها، IP داخلی و پورت فعلی WireGuard حفظ می‌شوند. فوروارد عمومی قبلی روی ایران حذف می‌شود. هر دو سمت باید تبدیل شوند؛ برای همین جفت سرور نیازی به کد جدید نیست. اگر هنوز به فوروارد عمومی قدیمی نیاز دارید، آن نصب را تبدیل نکنید.

تکرار این دستور روی حالت جدید تنظیمات را عوض نمی‌کند. پیش‌فرض 9999 پورت نصب موجود را خودکار تغییر نمی‌دهد. کدهای WGB2 تا زمان تبدیل صریح در حالت قدیمی قابل مدیریت هستند.

نسخه‌های full-routing قدیمی 0.1/0.2 قابل ارتقای مستقیم نیستند. ابتدا روی ایران سرویس‌های `wg-quick@wgb-exit` و `wg-bridge-network` را متوقف کنید تا دسترسی مستقیم برگردد؛ سپس روی هر دو سرور با مدیر قبلی `wg-bridge uninstall` را اجرا کنید. نسخه فعلی را ابتدا روی خارج و سپس با کد جدید WGB3 روی ایران نصب کنید. WGB1 سازگار نیست.

## حذف

```bash
wg-bridge uninstall
```

با `REMOVE` تأیید کنید. قواعد و مسیرهای متعلق به برنامه، رابط، سرویس‌ها، کلیدها و مدیر حذف می‌شوند. مقدار قبلی انتقال بسته IPv4 در صورت باقی‌بودن مقدار تنظیم‌شدهٔ برنامه بازگردانده می‌شود. بسته‌های مشترک سیستم حذف نمی‌شوند. خروجی تونل را در پنل جداگانه حذف یا غیرفعال کنید.

## نگهداری

```bash
journalctl -u wg-bridge-network -u wg-quick@wgb-exit --no-pager -n 60
```

MTU برابر 1380 است. جدول 51888 و اولویت‌های 18880/18881 به مسیر انتخابی اختصاص دارند؛ تداخل پیش از نصب یا تبدیل رد می‌شود. مسیریابی سفارشی و مدیر فایروال مستقل به بررسی دستی نیاز دارند. هنگام استفاده، فایروال را پاک نکنید؛ پس از تغییر فایروال، Restart و doctor را اجرا کنید. اسکریپت فایروال ارائه‌دهنده یا مبهم‌سازی پروتکل را تنظیم نمی‌کند.
