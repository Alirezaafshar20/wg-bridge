# WG Bridge

[English](README.md) | **فارسی**

[![Tests](https://github.com/itsalirezaw/wg-bridge/actions/workflows/test.yml/badge.svg)](https://github.com/itsalirezaw/wg-bridge/actions/workflows/test.yml) [![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

انتقال یک پورت IPv4 از سرور ایران به سرویس روی سرور خارج، از داخل WireGuard. نصب‌کننده پورت‌های آزاد تصادفی پیشنهاد می‌کند و کاربر می‌تواند پورت دلخواه و پروتکل TCP، UDP یا هر دو را انتخاب کند. عدد `8443` در مثال زیر صرفاً نمونه است. مسیر اینترنت عمومی سرور، سایر پورت‌ها و تنظیمات IPv6 تغییر نمی‌کنند.

```text
User → Iran:8443 → WireGuard → Outside service:8443
```

سرویس مقصد روی سرور خارج اجرا می‌شود. این روش اتصال ورودی را منتقل می‌کند؛ خروجی یک برنامهٔ پراکسیِ در حال اجرا روی ایران را بر اساس پورت ورودی آن انتخاب نمی‌کند. نصب‌های نسخهٔ 0.1 و 0.2 نیازمند حذف تانل قبلی و نصب مجدد هستند؛ مراحل در بخش «انتقال از نسخه‌های قدیمی» آمده است.

## Requirements

Ubuntu 22.04/24.04/26.04 LTS (شامل 26.04.1) یا Debian 12/13، دسترسی root، systemd، کرنل دارای WireGuard و IPv4 عمومی روی هر دو میزبان. پورت سرویس انتخابی در فایروال ارائه‌دهندهٔ سرور ایران و پورت UDP انتخاب‌شده برای ارتباط WireGuard روی خارج باید باز باشند. سایر وابستگی‌ها خودکار نصب می‌شوند.

```bash
apt-get update && apt-get install -y curl ca-certificates
```

## Install

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/itsalirezaw/wg-bridge/main/install.sh)
```

## پیکربندی

1. ابتدا روی **خارج** گزینهٔ **2 — Client** را انتخاب کنید. IP عمومی و پورت UDP وایرگارد را تأیید کنید؛ پورت سرویس مقصد و پروتکل (پیش‌فرض `both`) را انتخاب کنید. کنار مقدارهای پیشنهادی رنگی عبارت `Press Enter to use …` نمایش داده می‌شود؛ Enter مقدار پیشنهادی را می‌پذیرد و با تایپ عدد می‌توانید آن را تغییر دهید.
2. برنامهٔ مقصد روی خارج باید روی `0.0.0.0:8443` یا `10.204.0.1:8443` گوش کند؛ عدد را با پورت انتخابی جایگزین کنید. برنامه‌ای که فقط روی `127.0.0.1` یا IP عمومی گوش می‌کند، از آدرس خصوصی تانل قابل دسترسی نیست. این اسکریپت خود برنامه یا پنل مقصد را نصب نمی‌کند.
3. کد کامل **WGB2** را کپی کنید. روی **ایران** گزینهٔ **1 — Server** را انتخاب کنید، کد را وارد کنید و IP ایران و پورت محلی UDP وایرگارد را تأیید کنید. سپس پورت ورودی دلخواه را تعیین کنید؛ اگر پورت مقصد روی ایران آزاد باشد همان عدد پیشنهاد می‌شود؛ در غیر این صورت پورت آزاد دیگری پیشنهاد می‌شود. واردکردن عدد دلخواه نیز ممکن است. کد اتصال هنگام واردکردن قابل مشاهده است.
4. از یک دستگاه دیگر به `IRAN_IP:PORT` وصل شوید. کد اتصال باید کامل، همراه `WGB2.`، وارد شود. این کد حاوی کلید خصوصی است؛ در ویدیو یا فضای عمومی نشان داده نشود.

پورت سرویس و پورت ارتباط WireGuard دو کارکرد جدا دارند. تغییر پورت سرویس، بسته‌بودن مسیر UDP وایرگارد را برطرف نمی‌کند. ایران ارتباط رمزگذاری‌شده را به خارج آغاز می‌کند. هر نصب یک جفت سرور و یک نگاشت پورت دارد.

## مدیریت

```bash
wg-bridge
wg-bridge status
wg-bridge doctor
```

از هر مسیر با دستور `wg-bridge` منوی نصب‌شده را باز کنید؛ اجرای دوبارهٔ نصب‌کننده لازم نیست.

منو شامل وضعیت، عیب‌یابی، راه‌اندازی مجدد، نمایش کد، توقف و شروع، تغییر پورت ایران و حذف کامل است. برای تغییر فقط پورت ورودی ایران:

```bash
wg-bridge port 9443
```

کلیدها و پورت مقصد خارج حفظ می‌شوند. تغییر پورت ممکن است اتصال‌های فعال همان سرویس را قطع کند. برای تغییر پورت مقصد خارج یا پروتکل، هر دو سمت را با انتخاب جدید دوباره نصب و جفت کنید.

سرویس‌ها هنگام روشن‌شدن سرور شروع می‌شوند. با توقف WireGuard فقط پورت منتقل‌شده از دسترس خارج می‌شود؛ اینترنت مستقیم و مسیر سایر سرویس‌ها حفظ می‌شود. تست پورت عمومی را از یک دستگاه دیگر انجام دهید؛ اتصال‌های محلی خود ایران منتقل نمی‌شوند.

## ارتقا

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/itsalirezaw/wg-bridge/main/install.sh) --upgrade
```

این دستور نصب‌های سازگار نسخهٔ 0.3 را با حفظ کلیدها و پیکربندی به‌روز می‌کند. نصب‌های 0.1 و 0.2 که مسیریابی سراسری داشتند، پیش از جایگزینی برنامه یا تغییر شبکه رد می‌شوند.

## انتقال از نسخه‌های قدیمی

ابتدا روی **ایران** اینترنت مستقیم را برگردانید تا دانلود نصب‌کننده ممکن شود:

```bash
systemctl stop wg-quick@wgb-exit.service wg-bridge-network.service
```

سپس روی **هر دو سرور**، با مدیر نصب‌شده تانل قبلی را حذف کنید:

```bash
wg-bridge uninstall
```

با `REMOVE` تأیید کنید. تانل و کلیدهای قدیمی WG Bridge حذف می‌شوند. نسخهٔ 0.3 را ابتدا روی خارج و سپس ایران نصب کنید و **کد جدید WGB2** را به ایران بدهید؛ کدهای WGB1 سازگار نیستند. سرویس مقصد باید روی خارج باشد؛ پنلی که روی ایران باقی می‌ماند به تنظیم مستقل خروجی در خود برنامه نیاز دارد.

## حذف

```bash
wg-bridge uninstall
```

با `REMOVE` تأیید کنید. حذف از منو یا گزینهٔ `--uninstall` نصب‌کننده نیز در دسترس است. قوانین، کلیدها، رابط شبکه، سرویس‌ها و برنامهٔ متعلق به ابزار حذف می‌شوند؛ بسته‌های مشترک سیستم‌عامل باقی می‌مانند. مقدار قبلی IPv4 forwarding ایران، در صورت باقی‌بودن مقدار تحت مدیریت ابزار، بازگردانی می‌شود.

## نگهداری

```bash
journalctl -u wg-bridge-network -u wg-quick@wgb-exit --no-pager -n 60
```

MTU برابر `1380` است. انتقال پورت روی IPv4 انجام می‌شود و IPv6 سرور مستقل باقی می‌ماند. برنامهٔ خارج به‌دلیل SNAT، آدرس کاربر را `10.204.0.2` می‌بیند. پورت ورودی اشغال‌شده و تداخل زیرشبکهٔ تانل پذیرفته نمی‌شوند. policy routing سفارشی، زنجیره‌های مستقل nftables، پورت‌های منتشرشدهٔ Docker و بازخوانی فایروال نیازمند بررسی سازگاری‌اند. فایروال ارائه‌دهنده و استتار پروتکل توسط ابزار تنظیم نمی‌شوند.
