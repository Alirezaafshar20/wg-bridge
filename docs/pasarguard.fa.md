# تنظیم پنل پاسارگارد

[English](pasarguard.md) | **فارسی** · [راهنمای سایر پنل‌ها](panels.fa.md)

در این روش، خروجی اینباندهای انتخاب‌شدهٔ Xray در پاسارگارد از تونل موجود WG Bridge عبور می‌کند. کاربران همچنان به ایران متصل می‌شوند و ترافیکشان از خارج وارد اینترنت می‌شود. نیازی به نصب SOCKS یا ساخت هستهٔ WireGuard جداگانه در پنل نیست.

این راهنما بر اساس مستندات و کد ویرایشگر پاسارگارد تهیه شده است. نام گزینه‌ها بین نسخه‌ها متفاوت است و تمام نسخه‌های پاسارگارد به‌صورت عملی آزمایش نشده‌اند.

## ۱. بررسی تونل و نود

هر دو سرور باید WG Bridge نسخهٔ 0.4 یا جدیدتر را در حالت **panel-routing-v1** اجرا کنند. روی **نود ایران که Xray کاربران واقعاً روی آن اجرا می‌شود**، دستور زیر را بزنید:

```bash
wg-bridge doctor
```

بررسی handshake، خروج اینترنت با HTTPS و DNS با UDP باید موفق باشد. هندشیک به‌تنهایی کافی نیست. نصب قدیمیِ فوروارد پورت ابتدا باید طبق [راهنمای ارتقا](../README.fa.md) به حالت مسیریابی پنل تبدیل شود.

Xray ایران باید به آدرس مبدأ `10.204.0.2` و رابط `wgb-exit` دسترسی داشته باشد. اگر پنل مدیریتی و نود روی دو سرور جدا هستند، نصب تونل فقط روی سرور مدیریتی کافی نیست. فایل Compose رسمی پنل از `network_mode: host` استفاده می‌کند؛ تنظیم واقعی نود خودتان را هم بررسی کنید. کانتینر سفارشی با شبکهٔ bridge به تنظیم شبکهٔ جداگانه نیاز دارد.

## ۲. بازکردن تنظیمات هستهٔ متصل به ایران

1. وارد **نودها / Nodes** شوید، نود ایران را ویرایش کنید و انتخاب **پیکربندی هسته / Core Config** آن را ببینید.
2. وارد **هسته‌ها / Cores** شوید و همان پیکربندی را باز کنید. نوع هسته باید **Xray** باقی بماند.
3. در نسخه‌های جدید وارد **پیشرفته / Advanced → همه / All** شوید تا JSON کامل را ببینید. نسخه‌های قدیمی‌تر ممکن است ویرایشگر JSON را مستقیماً در پنجرهٔ پیکربندی هسته نمایش دهند.
4. قبل از ویرایش، JSON فعلی را کپی و نگه دارید. اگر چند نود از یک پیکربندی مشترک استفاده می‌کنند، ابتدا یک نسخهٔ جدا از همان پیکربندی بسازید و فقط به نود ایران موردنظر اختصاص دهید.

برای این روش هستهٔ WireGuard یا خروجی با پروتکل WireGuard نسازید. تونل را اسکریپت در سیستم‌عامل ساخته است؛ پنل با خروجی `freedom` از آن استفاده می‌کند.

## ۳. اضافه‌کردن خروجی، DNS و مسیریابی

**نمونهٔ زیر فقط بخش‌های مربوط به اتصال تونل است و جایگزین کامل تنظیمات هسته نیست.** بخش `inbounds`، کاربران، API، policy، آمار و سایر تنظیمات خود را حفظ کنید. بخش‌ها را با JSON فعلی ادغام کنید؛ کلید تکراری `outbounds`، `dns` یا `routing` نسازید.

- خروجی `wg-out` را به آرایهٔ موجود `outbounds` اضافه کنید. خروجی‌های قبلی و نام دقیق تگ‌های آن‌ها را نگه دارید. `DIRECT` و `BLOCK` در این نمونه نام‌های قالب پیش‌فرض پاسارگارد هستند.
- برای این روش انتخابی، `DIRECT` اولین خروجی باشد. Xray ترافیک بدون قانون منطبق را به اولین خروجی می‌فرستد؛ اگر `BLOCK` اول باشد، آن ترافیک قطع می‌شود. کاربران انتخاب‌شده با قانون مشخص به `wg-out` می‌روند.
- بخش موجود `dns` را مطابق نمونه تنظیم کنید. تگ `wg-dns` باید روی **کل شیء DNS** باشد، نه فقط یکی از سرورها. پورت پیش‌فرض این DNSهای مبتنی بر IP، برابر `53/UDP` است. پیش از ادغام، تنظیمات تفکیک DNS، تگ اختصاصی سرورها و مقادیر hosts قبلی را بررسی کنید؛ DNSهای حالت local از مسیریابی موردنظر عبور نمی‌کنند.
- دو قانون نمونه را به آرایهٔ موجود `routing.rules` اضافه کنید. قوانین داخلی API و مسدودسازی را جلوتر نگه دارید و قوانین جدید را قبل از قوانین عمومی `DIRECT` بگذارید. سایر تنظیمات Routing را حفظ کنید.
- به‌جای `YOUR_INBOUND_TAG` مقدار دقیق `tag` اینباند کاربر را از آرایهٔ `inbounds` وارد کنید. این مقدار نام کاربر، UUID یا شماره پورت نیست. بزرگی و کوچکی حروف مهم است؛ اینباند API پنل را انتخاب نکنید.

```json
{
  "outbounds": [
    {
      "tag": "DIRECT",
      "protocol": "freedom"
    },
    {
      "tag": "wg-out",
      "protocol": "freedom",
      "sendThrough": "10.204.0.2",
      "settings": {
        "domainStrategy": "ForceIPv4"
      },
      "streamSettings": {
        "sockopt": {
          "interface": "wgb-exit",
          "domainStrategy": "ForceIPv4"
        }
      }
    },
    {
      "tag": "BLOCK",
      "protocol": "blackhole"
    }
  ],
  "dns": {
    "servers": ["8.8.8.8", "1.1.1.1"],
    "queryStrategy": "UseIPv4",
    "tag": "wg-dns"
  },
  "routing": {
    "rules": [
      {
        "type": "field",
        "inboundTag": ["wg-dns"],
        "outboundTag": "wg-out"
      },
      {
        "type": "field",
        "inboundTag": ["YOUR_INBOUND_TAG"],
        "outboundTag": "wg-out"
      }
    ]
  }
}
```

برای چند اینباند، فهرست تگ‌های قانون دوم را با نام‌های واقعی اینباندهای خود جایگزین کنید؛ مثلاً:

```json
["VLESS-IN", "TROJAN-IN", "SS-IN"]
```

دو فیلد راهبرد IPv4 برای سازگاری با Xray قدیمی و جدید درج شده‌اند. ویرایشگر ممکن است نمایش آن‌ها را یکسان‌سازی کند. پس از ذخیره بررسی کنید که خروجی همچنان `sendThrough`، `sockopt.interface` و راهبرد تبدیل دامنه به IPv4 را داشته باشد.

در این روش DNS داخلی نمونهٔ Xray و اینباندهای انتخاب‌شده از خارج عبور می‌کنند. ترافیک بدون قانون منطبق از اولین خروجی یعنی `DIRECT` می‌رود؛ DIRECT مسیر جایگزینِ اتصال ناموفق `wg-out` نیست. اگر بعداً اینباند جدیدی ساختید و باید از تونل عبور کند، تگ آن را هم به قانون کاربران اضافه کنید. پورت `9999` یا شماره پورت اینباند را در فیلد `port` قانون Routing وارد نکنید؛ آن فیلد پورت مقصد است.

## ۴. ذخیره، اعمال و آزمایش

1. پیکربندی هسته را ذخیره و روی نود ایران اعمال کنید. اگر گزینهٔ **راه‌اندازی مجدد گره‌ها / Restart Nodes** هنگام ذخیره وجود دارد، از آن استفاده کنید؛ در غیر این صورت هسته یا نود مربوط را از پنل مجدداً راه‌اندازی کنید. پیکربندی مشترک ممکن است چند نود را تحت‌تأثیر قرار دهد.
2. وضعیت اتصال نود و نبود خطای تنظیمات یا انتخاب رابط را در لاگ هسته بررسی کنید.
3. یک کلاینت واقعی را دوباره وصل کنید؛ IP خروجی باید IPv4 عمومی سرور خارج باشد. بازشدن سایت با نام دامنه و یک برنامهٔ دارای UDP را هم بررسی کنید.

آدرس Host یا کانفیگ کاربران همچنان باید ایران و پورت عادی اینباند باشد. آن را به IP خارج، `10.204.0.2` یا پورت انتقال WireGuard تغییر ندهید. این راهنما مسیر پیش‌فرض اینترنت خود سرور را تغییر نمی‌دهد. خروجی تونل فقط IPv4 است.

## اگر اتصال هنوز کار نمی‌کند

- **هندشیک برقرار است ولی doctor خطا دارد:** ابتدا مسیریابی تونل، NAT یا اینترنت خارج را اصلاح کنید؛ هنوز نوبت تغییر بیشتر پنل نیست.
- **doctor موفق است ولی IP خروجی کاربر ایران است:** پیکربندی هستهٔ انتخاب‌شدهٔ نود، تگ دقیق اینباند، قوانین direct با اولویت بالاتر و اعمال‌شدن تغییرات را بررسی کنید.
- **IP خارج نمایش داده می‌شود ولی دامنه‌ها باز نمی‌شوند:** تگ عمومی `wg-dns`، قانون آن و DNSهای local یا مقادیر hosts قدیمی را بررسی کنید.
- **خطای نبود رابط یا ناتوانی در انتخاب آدرس:** Xray روی میزبان یا شبکه‌ای اجرا می‌شود که به `wgb-exit` یا `10.204.0.2` دسترسی ندارد.
